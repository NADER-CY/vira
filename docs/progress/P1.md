## How to resume

1. `git fetch origin && git checkout feat/p1-foundations`.
2. Read this file and the open items below; CI status: `gh api repos/NADER-CY/vira/actions/runs?branch=feat/p1-foundations`.
3. CI failure details are emitted as check-run annotations (`.github/scripts/run.sh`), readable with
   `gh api repos/NADER-CY/vira/check-runs/<job-id>/annotations` (job logs themselves are not downloadable from the session).
4. Generated files that need a toolchain the session lacks (npm lockfile, Flutter platform folders, `pubspec.lock`,
   golden images, web screenshots) are published by CI to `ci-evidence/<name>-<run_id>` branches; fetch them with git
   and commit the reviewed files.

Session environment notes (Claude cloud session): package registries are blocked; GitHub is reachable. Go modules are
fetched from GitHub (`GOPROXY=direct`) with a local proxy that serves golang.org/x modules from their official GitHub
mirrors; `go.sum` is verified against sum.golang.org in CI. A local PostgreSQL 16 runs the integration tests.
npm, pub.dev, Flutter and Docker images are only available in CI (GitHub Actions is the build environment).

## Decisions taken in Phase 1 (within the accepted ADRs)

| Topic | Decision |
|---|---|
| ADR-013 state management | Riverpod 3 (`flutter_riverpod`), navigation with go_router (StatefulShellRoute) |
| ADR-012 hosting path | Local Docker Compose and a single-VM Compose staging (prepared, not deployed); Kubernetes/IaC deferred to gate L |
| ADR-020 observability | Structured JSON logs (slog) + W3C trace ids + health/readiness; full OTel stack deferred to gate L |
| Secrets | `.env` generated locally by `scripts/dev-setup.sh`; staging secrets on the server only; gitleaks on full history in CI |
| Object storage (local) | MinIO built from the upstream source release (no images are published any more); AGPL, local/CI only |
| Web icons | Material Symbols bundled as SVG at build time (no CDN, DS-05/DS-06) |
| Tokens | `design/tokens/vira.tokens.json` → generated CSS + Dart, WCAG AA contrast checked in CI |
| Admin auth | Password + TOTP, HttpOnly SameSite=Strict session cookie, CSRF header, 8 h absolute / 15 min idle |
| Seller web | Same backend/identity as the app; sign-in gated by `seller.web_portal` (built in Phase 4) |
| Regulated capabilities | 8 flags locked off in code and by a DB CHECK constraint; admin attempts → 409 `feature_locked` + audit |
